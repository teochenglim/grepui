# RELEASE v0.14.0: LLM traces, step L1 (trace layouts and Connect)

**Status:** ready
**Design choices (ARCH 06):** D3
**Exit gate:** an OpenInference trace sent to a trace v2 table can be filtered by any attribute and opened with its messages, tokens and project; the Connect page's LLM headers are accepted by GreptimeDB
**Depends on:** 0.13
**Requirements:** R-AI1 R-AI2

## Scope

- Detect the attribute layout of the org's traces table: flat (`greptime_trace_v1`) or JSON2 (`greptime_trace_v2`, GreptimeDB v1.3.0+)
- One attribute accessor for filters, the span panel and the trace detail; keys are bound parameters
- Connect page section for LLM SDKs (OpenInference, OTel GenAI)
- Playground `--llm-data`: OpenInference-shaped demo traces in a trace v2 table

## Notes

Built: see ADR 0015. Verified live on GreptimeDB v1.3.0: spans shaped like OpenInference output are sent to a trace v2 table and read back through the API with exact filter results (`ac_0_14_1_both_layouts_live`), and the headers the Connect page publishes are accepted while a v1 pipeline header on the same table is refused (`ac_0_14_2_connect_headers_accepted_live`). The real OpenTelemetry Python SDK with the OpenInference OpenAI instrumentor (talking to a local fake OpenAI endpoint) was also sent to a v2 table by hand and read back: model, token counts, indexed messages and the `openinference.project.name` resource attribute all arrived as the Connect snippet describes. Browser pass: the Traces page on a v2 table (JSON-attributes badge, `llm.model_name=gpt-4o` filter, waterfall, span panel with messages and tokens) and the Connect page's LLM card (`images/ui_traces_llm.png`, `ui_trace_llm_detail.png`, `ui_connect_llm.png`).

Limits: not tested with the Phoenix package `arize-phoenix-otel` itself (the plain OpenTelemetry exporter and the OpenInference instrumentor were); an org reads one traces table from its own database, so LLM traces need their own org and database (or `--traces-table`); the trace page shows raw attributes, LLM-aware views are step L2; attribute values over 32 KiB are cut in the detail view; the Services page lists the LLM service and its span count from a v2 table, but its RED request and error rates count only server and consumer spans, and OpenInference spans are internal, so they read 0 until the LLM analytics step (L3).
