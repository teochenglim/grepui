# RELEASE v0.11.0: Access control, multi-tenancy, SSO and audit

**Status:** ready
**Design choices (ARCH 06):** D2 D3
**Exit gate:** a viewer cannot read another org's streams or write state; SSO login maps claims to a role; every action appears in the audit table
**Depends on:** 0.10
**Requirements:** R-C1 R-C2 R-C3 R-C4 R-C5 R-C6

## Scope

- Local users, organizations (tenants), roles, sessions; multi-tenant UI with org switcher, branding and org admins
- RBAC enforced in the query layer for every endpoint
- API tokens and service accounts
- OpenID Connect SSO
- Audit trail with search

## Notes

Replaces the earlier plan for a single `--basic-auth` flag. `--no-auth` exists for local use and is refused when listening on a non-loopback address.

**What was built.** Sign-in (first-run setup, password login with argon2id, sessions as hashed cookies with expiry, logout, password change); roles per org (viewer, editor, admin) and platform admins; deny by default through one route table (ADR 0012); API tokens (shown once, hashed, scoped, revocable, expiring, rate-limited); OpenID Connect with PKCE and ID-token verification (RS256 and ES256), claim-to-role mapping, and a TLS client; orgs stored in the state store (platform admins create them, optionally creating the database, and delete them with a cascade over state rows, never telemetry); members, tokens, branding and audit search per org; an append-only audit trail with a queue and writer. UI: sign-in and first-run pages, who-am-I menu with sign out, org switcher with branding, Administration (members, tokens, audit, branding) and Platform (orgs, users, audit). Schema version 5 (`grepui_audit`), so run `grepui migrate`. The playground signs in as `admin` / `grepui-demo-admin` (demo only). New flags `--no-auth`, `--session-hours`, `--token-rate-per-min`, `--oidc-*`. New dependencies argon2, ring, rustls, tokio-rustls, webpki-roots, base64; `deny.toml` allows the Mozilla root-certificate data licence.

**Limits, stated.** Roles are per org: no stream or folder permissions (R-C2 asks for them) and no quotas or sources (v0.12.0). Older features still write `local` as the owner; the audit trail has the real user. The first-administrator race and the OIDC pending login rely on write-then-read, not compare-and-set. Identities are cached for 5 s per process. A change by a platform admin reaches other replicas within about 5 s. OIDC has no discovery (the endpoints are flags), no refresh tokens and no back-channel logout; the provider session is not ended on sign-out. The cookie has no `Secure` flag (grepui speaks plain HTTP; set it at the proxy). Audit rows queue in memory, so a crash can lose the last few. Not exercised in a browser: the first-run setup page, the SSO button against a real provider, the members and branding forms, the Platform users tab. Verified against a real provider: not at all, only against a local stand-in; the TLS client was checked against example.com (and a wrong-host certificate was refused). Live on v1.3.0: first admin once, cross-org blocking, org create with a real `CREATE DATABASE` and the delete cascade, audit search by user, action and time.
