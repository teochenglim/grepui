## Notes

First release with GreptimeDB DDL writes. They need `--admin-writes` (the stand-in for an admin role until v0.11.0, ADR 0008), are generated from templates in `src/admin.rs` and re-checked by `admin::check` (a refusal test covers `DROP TABLE` on telemetry and state tables, stacked statements and odd TTLs). Each write logs an `audit` line; the audit table comes with v0.11.0.

Rollup: template `traces_red` creates the sink `<traces_table>_red_1m` and the flow `grepui_<db>_red_1m` (per minute and service: requests, errors, sum and max duration of server and consumer spans). v1.3.0 flows are the batching kind and recompute the windows that received writes from the source, so a backfill and the flow agree exactly (verified live), and re-running a backfill changes nothing; the flow only sees writes after creation, so history needs the backfill (chunked by day, whole minutes, at most 31 days per request). The planner reads the rollup for windows over 24 hours when the sink exists (Services list, catalog, service summary and series), reports `meta.source = rollup_1m` and a note that p95 is unavailable; without a sink it reads raw spans and warns in `meta.note`. Operations and dependencies always read raw spans. The AC text says "warning"; the field is `meta.note`.

Retention: lists the TTL of the traces, logs and rollup tables (GreptimeDB echoes `7d` as `ttl=7days` and 90 days as `2months 29days 2h 52m 48s`, so both the text and approximate seconds are shown), previews how many rows are older than `now - ttl` without changing anything, and sets `ALTER TABLE ... SET 'ttl'` for `forever` or n hours, days or weeks (1 hour to 3650 days). Rows older than the TTL are removed by compaction later, not immediately. A tiering hint appears when raw spans outlive the rollup or are kept forever.

Verified live on a fresh v1.3.0: sink contents equal the generator's counts, errors, sums and maxima per service; the flow rolls up newly written spans (after `ADMIN FLUSH_FLOW`); create is idempotent; drop removes flow and sink; TTL preview is exact (the old spans expire, the new stay); TTL set and read back. Checked in a browser: Rollups (create, backfill) and Retention (preview), and the Services page on 7 days answering from the rollup. Not exercised in a browser: Drop, Apply TTL, the tiering hint. Metrics downsampling is not built; it will use the same gate as another template.
