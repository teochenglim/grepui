# RELEASE v0.13.0: Reports, RUM view and operate

**Status:** planned
**Design choices (ARCH 06):** D3 D7
**Exit gate:** a scheduled report arrives by email; RUM page renders from GrepRUM tables; two identical concurrent queries hit the DB once
**Depends on:** 0.12
**Requirements:** R-E1 R-O1 R-O2 R-O3 R-U1

## Scope

- Scheduled reports (HTML/CSV by email)
- RUM view over GrepRUM tables
- Result cache with single-flight, `/metrics`, graceful shutdown, read-only-user check

## Acceptance criteria

| AC | Reqs | Statement | Tests (≥2 each) |
|---|---|---|---|
| AC0.13.1 | R-E1 | A report renders a dashboard or saved view to HTML/CSV, runs on schedule once across replicas, and emails it; failures are recorded | `ac_0_13_1_report_renders_html`, `ac_0_13_1_report_runs_once`, `ac_0_13_1_report_failure_recorded` |
| AC0.13.2 | R-U1 | RUM view reads GrepRUM tables for views, web vitals, errors and sessions; absent tables give a clear "not installed" state | `ac_0_13_2_rum_queries_bound`, `ac_0_13_2_rum_absent_state`, `ac_0_13_2_rum_live` |
| AC0.13.3 | R-O1 | Identical concurrent queries run once; results expire by TTL; the key includes the role; memory is bounded | `ac_0_13_3_single_flight`, `ac_0_13_3_ttl_expiry`, `ac_0_13_3_key_includes_role`, `ac_0_13_3_bounded` |
| AC0.13.4 | R-O2 | `/metrics` exposes request counts, DB latency histogram, cache hits and alert evaluations | `ac_0_13_4_metrics_text`, `ac_0_13_4_counters_move` |
| AC0.13.5 | R-O3 | Shutdown drains in-flight requests; the pool respects limits; startup warns when the DB account can write | `ac_0_13_5_graceful_shutdown`, `ac_0_13_5_pool_limits`, `ac_0_13_5_warns_if_writable` |

## Notes

Session replay and PDF reports are not supported; ARCH 07 lists them as gaps.
