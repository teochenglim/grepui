## Notes

GreptimeDB pipelines are YAML-configured, not VRL scripts; this is a documented difference. Cipher-key field encryption is not implemented (redaction only).

**What was built.** *Pipelines:* list, view, save as a new version, delete (all versions or one), and a dry-run with stored or inline YAML and up to 20 sample records, through GreptimeDB's HTTP API; names are `<org>.<name>`; saving and deleting need `--admin-writes` and are logged. *Functions:* saved SQL snippets called as `@name(args)` in SQL mode and dashboard SQL panels, arguments bound. *Enrichment:* CSV upload to `enrich_<name>` (inferred types, optional key columns, replace), list, preview, drop, and a join helper that builds a starter query for SQL mode. *Redaction:* rules per field with `full`, `partial` or `hash` masks, applied by one layer to every JSON response and CSV/NDJSON export, including JSON attributes and dotted keys. UI: Pipelines, Functions, Enrichment, Redaction pages. No schema change (version stays 4); new flag `--pipeline-http`; no new dependency (CSV is written in the crate); ADR 0011.

**Limits, stated.** There are no roles until v0.11.0: `admin` is "started with `--admin-writes`", everyone else and every public link is a `viewer`, and a rule can exempt `admin`. Redaction does not see a renamed column, free text in a log body or `meta.sql`; other replicas apply a rule change within about 5 s; until the first load after startup data routes answer 503. A pipeline's own `<org>.` prefix is part of the name collectors send. Dry-run results show the transformed rows, not what the table would look like after ingest. Pipeline versions can only be removed, not edited. Function bodies are plain expressions (add your own parentheses); no recursion by construction. Enrichment re-upload needs `replace=true`; without key columns every row is appended. The pipeline create path of GreptimeDB requires a timestamp-index field (found by the live test). Not exercised in a browser: delete buttons, the file chooser, loading a pipeline into the editor, the function form, the redaction form. Live on v1.3.0: pipeline create/version/dry-run/delete, and the enrichment join against exact per-tier span counts.
