## Notes

RED is computed over entry spans (server and consumer kinds); a client span is the caller's view of the same request. p95 uses `approx_percentile_cont`, a sketch: the live test accepts 10% of the exact nearest-rank value, while requests, errors and the average are exact. A service with only client spans (the demo `postgres`) is listed with 0 requests and no latency.

Dependencies use one self-join (child span to parent span by trace and span id). It returned wrong, nondeterministic rows on GreptimeDB v1.2.1 and is correct on the pinned v1.3.0 (ADR 0007); `ac_0_5_3_dependencies_live` compares every edge with an answer computed from the generator, and runs the query twice to catch nondeterminism. Both spans must start inside the window, so a call that straddles the window edge is not counted. Calls inside one service are excluded unless `self_loops=true`. The map layout (`layout::graph`) is layered by longest call path, cycle-safe (a cycle edge is flagged `back`), and drawn by the page from plain coordinates.

The catalog note is the second writer to the state store: table `grepui_services` (key `org_id`, `service`; `updated_by` and `updated_ms` for the audit log in v0.11.0; clear is a soft delete). The schema version is now 2, so an existing store needs `grepui migrate` (the playground does it itself; `serve` warns). Notes are optional on read: a store that is not migrated does not hide a service. Checked in a browser: services list, service page with charts and note form, service map (an arrow that skips a column arcs over the nodes between), catalog with a saved note. Not exercised in a browser: the cycle (`back`) and self-loop drawings (covered by layout tests only), editing from the catalog table.
