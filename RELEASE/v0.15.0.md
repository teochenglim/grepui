# RELEASE v0.15.0: LLM traces, trace-level views (steps L2, L4, L5 and content protection from L6)

**Status:** ready
**Design choices (ARCH 06):** D3
**Exit gate:** an OpenInference trace opens with its conversation, tool calls, documents, tokens, cost and evaluations; its agent graph has the nodes and edges computed from the batch that was sent; a viewer sees prompts masked and an admin sees them whole
**Depends on:** 0.14
**Requirements:** R-AI3 R-AI4 R-AI7 R-AI8 R-AI9

Why one release: all four steps are about one trace (the normalised span view, what is attached to it, how it is drawn, who may read its content), they share the normaliser in `src/llm.rs`, and content protection must ship with the views it protects.

## Scope

Step L2, LLM span views (ARCH 08 sections 6.2 and 6.3):

- `src/llm.rs` (built): one pure normaliser from OpenInference (first) and `gen_ai.*` (fills gaps); indexed messages put back by number, nested JSON accepted, embedding vectors counted not shown
- Trace detail carries the normalised view per span and a trace summary (model calls, tokens, cost, models, tools, session, user)
- UI: kind badges in the waterfall, kind filter chips on the Traces page (JSON tables), an LLM span panel (transcript, tool calls, token and cost chips, retrieval documents, long values collapsed), an "LLM steps" tab
- Per-org price table (`price` rows, USD per million tokens; `GET/PUT/DELETE /orgs/{org}/llm/prices`, write admin) fills a missing `llm.cost.total`; a reported cost is never replaced

Step L4, evaluations and annotations:

- Read `annotation.*`, `evaluation.*` and `gen_ai.evaluation.result` (attribute or event) into the view (`evaluations: [{name, label, score, explanation, source}]`)
- Human feedback in the state store (`feedback` rows, org scoped; thumbs, score, label, note, author, per trace or span); `GET/PUT/DELETE /orgs/{org}/llm/feedback`; editors write, viewers read; shown in the span panel and the trace header

Step L5, agent graph:

- `GET /orgs/{org}/traces/{id}/agent-graph`: nodes from `graph.node.id`/`graph.node.name`, `agent.name`, `gen_ai.agent.name`, edges from `graph.node.parent_id` and span parentage; calls, errors, p95, tokens and cost per node and edge; a pure builder tolerant of cycles and orphans; the UI reuses the service-map drawing; in the open binary, no gate

Step L6a, content protection:

- Prompt, completion, tool argument, document and `gen_ai.*` message attributes are masked by default for roles below admin through the existing redaction layer (no second mechanism); org setting `llm_content: hidden|masked|visible`; public links always masked; size caps hold in the span panel, exports and reports

## Notes

ADR 0016 records: one normaliser in Rust (the browser only draws it); evaluations are read from the span (no evaluator runs in grepui); feedback is a state-store kind, not a trace-table write; content protection reuses the redaction layer and defaults to masked below admin; the graph is computed per request from the trace's spans; prices are `price` rows in `grepui_alert_items`.

Open point to settle while building: how `gen_ai.evaluation.result` arrives (event or attribute) on a real v2 table; probe and record it in ARCH 08.

Limits to carry into the notes: grepui does not run evaluators or replay prompts; the graph shows what the instrumentation emitted.

## Built

See ADR 0016. Verified: 22 offline tests over a v2-shaped span set behind `MemStore` (indexed order, GenAI gaps, vectors, price estimate, summary, evaluations from attributes and events, feedback round trip, graph with explicit `graph.node.*`, cycles and orphans, masked, hidden, visible and public-link modes), and live on GreptimeDB v1.3.0: `ac_0_15_4_graph_matches_batch_live` sends a generated OpenInference batch to a real v2 table and compares the agent graph of three traces (edges and call counts) with the graph computed from the generated spans. Browser pass (admin, playground with `--traces-table llm_traces`): kind chips on the Traces page, waterfall kind badges, trace chips (model calls, tokens, cost, models, tools, session, user), LLM span panel with transcript, response and tool call, LLM steps tab, agent graph, feedback thumbs, Administration > LLM tab (prices, content mode) (`images/ui_traces_kinds.png`, `ui_trace_llm_span.png`, `ui_trace_llm_steps.png`, `ui_agent_graph.png`, `ui_admin_llm.png`).

Review follow-up: CSV bodies and nested JSON containers are masked too (`ac_0_15_5_caps_in_export_and_reports`, unit test `nested_containers_and_csv_are_protected`). Limits: masking is by attribute name from a denylist (a prompt in another attribute, or renamed by a SQL alias, is not recognised); the masked and hidden modes were exercised through the API tests, not in a browser as a viewer; `gen_ai.evaluation.result` events were read in both attribute shapes but never seen from a real SDK; feedback lists are read per trace from all of the org's feedback rows (capped at 20,000); the agent graph shows what the instrumentation emitted; grepui does not run evaluators or replay prompts.
