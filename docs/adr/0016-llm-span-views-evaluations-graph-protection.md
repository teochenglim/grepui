# 0016 LLM span views, evaluations, agent graph and content protection

Status: Accepted (v0.15.0, LLM track steps L2, L4, L5 and the masking part of L6).

## Context

Step L1 (ADR 0015) made OpenInference traces storable and filterable, but the trace page showed raw attributes: a chat of twenty messages was forty rows named `llm.input_messages.7.message.content`. Prompts and completions are also the most sensitive data grepui now shows, and nothing stopped a viewer reading them.

## Decision

- **One normaliser, in Rust.** `llm::normalise` turns a span's attributes into `{kind, model, provider, tokens, cost, messages, tool, documents, embeddings, input, output, session, user, agent, evaluations, ...}`. OpenInference is read first; `gen_ai.*` fills what it leaves out (kind from `gen_ai.operation.name`, model, tokens, conversation id, JSON messages with `parts`, system instructions). Flattened indexed attributes are rebuilt by numeric index (so index 10 follows 2), nested JSON is accepted. The browser only draws it. `layout::waterfall` attaches it as `llm` to each span row; the API adds a trace summary that counts model calls only, so a parent span that rolls tokens up is not counted twice.
- **Embedding vectors are counted, not sent**: the view carries the dimension count, the raw attribute becomes `[vector, N dimensions]` (the view is built first, then the panel's copy is summarised).
- **Cost.** A reported `llm.cost.*` is used as is. A per-org price table (`price` rows in `grepui_alert_items`, dollars per million tokens, admin writes, `GET/PUT/DELETE /llm/prices`) fills a missing total and marks it `estimated`; a reported cost is never replaced.
- **Evaluations are read, not run.** `annotation.*` and `evaluation.*` attributes (single or indexed) and `gen_ai.evaluation.result` events become `evaluations` on the span. Human feedback is a state-store kind (`feedback`): one row per person and target (trace or span), updated in place, soft-deleted, editors write, everyone reads, org scoped (`GET/PUT/DELETE /llm/feedback`).
- **Agent graph** (`GET /traces/{id}/agent-graph`, `agent_graph::build`): a node per `graph.node.id`, else per agent, tool, model, retriever and so on; an edge from the nearest ancestor that is itself a step, or from an explicit `graph.node.parent_id`. Plain spans in between are skipped. Cycles and missing parents are tolerated by a hop limit and a seen-set. Positions come from the service map's layered layout; the page also lists every node, so a lone step is not lost. It is in the Apache-2.0 binary with no gate.
- **Content protection reuses the redaction layer.** `llm::protect` runs inside `api::redaction::layer`, so no handler has code for it: attribute keys that hold content (`*.message.content`, `input.value`, `output.value`, `function.arguments`, document and embedding text, `gen_ai.*` messages, annotation explanations) and every content-like key inside an `llm` view are masked (`[masked: N characters]`) or removed. The org setting `llm_content` is `masked` (default), `hidden` or `visible`, and applies to everyone below admin; `effective_mode` makes a public link never more than masked. JSON and NDJSON bodies are covered, reports apply the same function. Roles remain the stand-in from ADR 0010 and the real ones from ADR 0012.

## Consequences

Viewers and editors see lengths and structure, not prompts, unless an admin changes the setting; that is a behaviour change for anyone who had read prompts as a viewer in 0.14. The masking is by attribute name: a prompt copied into some other attribute, or written by a SQL query under another alias, is not recognised (the same limit as ADR 0010). JSON, NDJSON and CSV bodies are all covered (a CSV column named like a content attribute is masked, and JSON inside a cell is protected). Content containers written as nested JSON (`llm.input_messages`, `retrieval.documents`, `embedding.embeddings`, ...) are masked whole. The list of content attributes is a denylist of the OpenInference and `gen_ai.*` names; an unknown instrumentation that puts prompts under another name is not covered until the name is added to `CONTENT_SUFFIXES` (a security review suggested an allowlist; for free-form attribute maps that would hide most attributes, so the denylist stays and its limit is stated). `gen_ai.evaluation.result` events were handled for both attribute shapes the conventions allow but not exercised against a real v2 table. No schema change, no new dependency.
