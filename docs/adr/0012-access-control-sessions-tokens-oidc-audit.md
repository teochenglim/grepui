# 0012 Access control: sessions, tokens, OpenID Connect and the audit trail

Status: Accepted (v0.11.0).

## Context

Until v0.10.0 everyone was an admin of the one `default` org, with `--admin-writes` and a viewer/admin split standing in for roles. The release needs people, orgs that platform admins create and delete, API tokens, single sign-on and an audit trail, with deny by default and without a second dependency besides GreptimeDB.

## Decision

- **Deny by default, in one table.** `auth::access_for(method, route template)` classifies every route as anonymous, signed-in, an org role (viewer, editor, admin) or platform admin; a template that is not in `api::ROUTES`, or a method the table does not name, is `Deny`. Reads need viewer (admin for members, tokens, audit and redaction rules; editor for destinations), every state change in `WRITE_ROUTES` needs editor, and the families that change the org itself or run DDL need admin. Tests walk `ROUTES` against the table, send an anonymous and a bad-token request to every route, and run an isolation matrix (org A user, org B user, org A admin, platform admin, anonymous) over every route and both orgs. The layer is a `route_layer`, so it sees the matched template and never a spelling of the path; the org is the decoded path segment. An org that does not exist and one the caller may not see both answer 403.
- **Three kinds of caller.** A person has a session: a random 256-bit cookie (`HttpOnly`, `SameSite=Strict`), only its SHA-256 stored, 12 hours by default. A service account has a bearer token `gu_<org>.<random>`, shown once, only its hash stored, scoped to one org and a role no higher than its creator's, revocable, expiring if asked, rate-limited per token (default 600 a minute). With `--no-auth` the caller is the implicit admin of everything, nothing is audited, and the process refuses to listen on a non-loopback address. Requests made with the cookie that change state must come from this site (`Origin`, else `Sec-Fetch-Site`); tokens carry no ambient credential and skip that. Identities are cached in memory for 5 s (a revoke or logout in this process is immediate; in another replica it takes up to 5 s).
- **Passwords** are argon2id with a random salt (minimum 10 characters); logins for an unknown or disabled user cost the same time; ten tries a minute per username. The first administrator is created through `POST /auth/setup` only while no user exists; GreptimeDB has no compare-and-set, so a marker is written and read back and a racing second setup loses.
- **Orgs and users live in the state store.** Users (with their org roles), org definitions (database, tables, branding), sessions, OIDC logins and tokens are kind-tagged rows of `grepui_alert_items`, platform rows under the pseudo org `_platform` (which no route can name). The `default` org still comes from the flags. A platform admin creates an org by naming its database (validated; never the state database, a system database or one another org uses; optionally created with one fixed `CREATE DATABASE IF NOT EXISTS`); `Orgs` is reloaded every 5 s and at once on the replica that changed it. Deleting an org soft-deletes every state row it owns (views, notes, folders, dashboards and shares, alerts and their kin, functions, redaction rules, tokens, memberships) and never touches telemetry.
- **OpenID Connect** is the authorization code flow with PKCE: the pending login (state hash, nonce, verifier) is a one-time row, so any replica can finish it; the callback exchanges the code server to server, then verifies the ID token. `auth::jwt` accepts RS256 and ES256 only (never `none` or HMAC), checks the signature against the provider's JWKS, issuer, audience (and `azp`), expiry, not-before, issued-at and the nonce, with 60 s of skew. The configured claim is mapped to roles by `--oidc-role-map value=role@org` (or `value=platform_admin`); roles are re-derived at every sign-in, and an account with no mapped role is refused. Endpoints are configured explicitly (no discovery yet).
- **TLS client.** OIDC providers are HTTPS, so grepui gains a TLS client (rustls with the ring provider and the Mozilla roots, `src/http.rs`); the runtime image stays `distroless/base-nossl` because nothing here uses OpenSSL. The same client reads chunked responses. New dependencies: argon2, ring, rustls, tokio-rustls, webpki-roots, base64. `deny.toml` allows `CDLA-Permissive-2.0`, the licence of the root-certificate data.
- **Audit.** One row per request that reads data or changes state (who, route, target, `from`/`to`, rows from the `x-grepui-rows` header, status, outcome, the query string as detail; the token of a public link never appears) plus sign-in, administration and platform events. A bounded queue and one writer task insert batches through `AppState::write`; `grepui_audit` has a 400-day TTL, rows have random ids, and the API has search only (`GET .../audit`, `GET /platform/audit`, windows of at most 31 days). The write gate allows only `INSERT`, so nothing can update or empty it. Redaction now takes its role from the caller's role in the org; `--admin-writes` only matters without sign-in.

## Consequences

Roles are per org with no finer grain: stream and folder permissions (R-C2's wording) are not built, and quotas and sources wait for v0.12.0. `owner`, `created_by` and similar fields on older features still say `local`; the audit trail has the real name. Memberships live inside the user row, so one read answers "what may they do", and two admins editing the same person at once can overwrite each other. The org list is capped by the store's 1000-row reads. Rate limits and caches are per process. A leaked cookie or token works until it expires or is revoked; `Secure` on the cookie is the reverse proxy's job.
